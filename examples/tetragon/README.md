# Tetragon export source

Use a **node-local** Tetragon JSONL export containing `process_exec` and
`process_connect` events. Tetragon execution events are generated by a default
installation, whereas connect events require appropriate sensor/tracing-policy
configuration. Check that your actual export contains both record types before
expecting correlation.

This collector intentionally does not infer network activity from process
execution. It fails on unsupported protocols, missing stable process IDs,
malformed target events, unexpected node names, and missing stable container
identity. Unrelated JSON event types are checkpointed and skipped.

Start locally (example):

```sh
go run ./cmd/server -data ./data/journal.jsonl
# On the Linux node where Tetragon writes the export:
go run ./cmd/collector -node "$(hostname)" -export /var/log/tetragon/tetragon.log -checkpoint ./data/source.json
```

For deterministic fixture tests, use `-follow=false` with a complete JSONL
file. Checkpoints are linked to device, inode, node name, and boot ID.
Log rotation/truncation and host reboots intentionally stop collection; rotate
only under operational supervision and preserve old files until drained. Do not
remove a checkpoint unless willing to replay the full new source. Recovery from
unexpected rotation currently requires an operator and is NOT lossless.

Warning: Tetragon JSONL may contain process command-line arguments and other
secrets. Do not expose the source log or journal. Run the API on loopback or
with HTTPS, authentication, and network access restrictions.
